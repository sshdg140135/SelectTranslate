# ADR-0002：中键"按下即触发 + 默认拦截 + Ctrl 旁路"

- 状态：已接受
- 日期：2026-11-04
- 相关：`docs/product/PRD.md` §5.2、`requirements.md` REQ-01.x

## 背景

鼠标中键在 Windows 上的原生语义并不统一：

- 浏览器：自动滚动（按下进入滚动模式，移动鼠标滚动页面）。
- 部分应用：后台打开链接、粘贴选中内容、关闭标签页。
- 绘图/IDE：平移画布。

如果直接拦截中键，会破坏这些原生行为；如果不拦截，又无法"按下即翻译"。需要决定：触发方式、是否拦截、冲突怎么解。

候选：

| 方案 | 说明 | 问题 |
|---|---|---|
| A. 长按中键触发 | 类似 uTools 超级面板的长按右键 | 慢；与浏览器滚动模式冲突更严重；用户学习成本高 |
| B. 中键按下即触发，不拦截 | 翻译的同时保留原生行为 | 浏览器会同时进入自动滚动，体验混乱 |
| C. 中键按下即触发并拦截，Ctrl 旁路 | 默认吞掉中键，按住 Ctrl 时放行 | 用户想用原生滚动时需按 Ctrl，有学习成本 |
| D. 默认键盘快捷键（如 Ctrl+Q） | 无冲突 | 不符合"鼠标顺手"的诉求 |

## 决策

采用 **C**：默认监听中键**按下**并吞掉该次按下/抬起；按住 **Ctrl** 时不拦截、不翻译；快捷键可在设置中改绑为其他鼠标键或键盘组合；托盘提供"暂停翻译"。

## 理由

1. "按下即触发"比长按快，符合"按一下就出现"的产品预期。
2. 拦截是翻译体验的前提：不拦截会出现"卡片出现 + 页面开始滚动"的双重反馈。
3. Ctrl 旁路把"原生行为"完整保留，且 Ctrl 是浏览器自动滚动的常用搭配（Ctrl+滚轮缩放），记忆成本低。
4. 可改键 + 暂停 + 黑名单构成三层退路，覆盖冲突场景。

## 后果

- 用户第一次遇到"中键不能滚动"会困惑，需要在首次向导与 README 中明确说明 Ctrl 旁路。
- 需要处理"吞掉 down 必须吞掉配对的 up"，否则目标应用可能收到不完整事件。
- 需要处理提权窗口：钩子对提权窗口无效，需提示以管理员身份运行。
- 需要防护钩子被系统摘除（定时重建、睡眠恢复后重建）。

## 被否决的方案

- **A 长按**：慢，且长按本身与滚动模式冲突。
- **B 不拦截**：双重反馈，体验不可接受。
- **D 纯键盘**：丢失"鼠标顺手"的核心卖点，仅作为备用快捷键保留（`hotkey.keyboard`）。
