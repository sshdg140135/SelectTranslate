# 竞品调研：Snipaste 与 uTools

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-04 |
| 目的 | 确定"轻量常驻 + 面板式取词"的产品形态是否成立 |
| 结论 | 形态成立：交互学 uTools 的"选中即出结果"，体量与常驻体验学 Snipaste |

## 1. Snipaste

**定位**：截图 + 贴图工具，常驻托盘，快捷键唤起，用完即走。

**技术事实（公开可查）**：

- C++ 与 Qt 6 实现。官方版本历史里明确出现"升级到 Qt 6.2.4""支持对 Qt 5.11+ 应用进行界面元素检测""Linux 适配 qt6ct"等记录，可确认是 Qt 6 的 C++ 原生程序（[官方下载页/版本历史](https://zh.snipaste.com/download.html)）。
- 便携单 exe、多平台（Windows/macOS/Linux）、支持 ARM64、无运行时安装负担。
- 闭源，2.0 起商用需授权，个人免费。

**可借鉴**：

- 托盘常驻 + 全局快捷键的"无感"体验：启动快、占用小、不打扰。
- 多屏与高 DPI 处理成熟（截图场景对坐标精度要求极高）。
- 便携分发：解压即用，降低朋友间的传播成本。

**不照搬**：截图/标注/贴图能力、付费 Pro 模式、多平台（v1.0 只做 Windows）。

## 2. uTools

**定位**：工具箱平台，插件化，"超级面板"是面向鼠标的快捷入口。

**技术事实（本机可验证）**：

- Electron 应用。本机安装目录 `%LOCALAPPDATA%\Programs\utools` 下存在 `resources/app.asar`、`chrome_100_percent.pak`、`LICENSE.electron.txt`、`ffmpeg.dll`，并附带原生 Node 模块（`addon/win32-x64.node`）处理系统级能力。
- 安装包 200MB 级、常驻内存高，与"小巧无感"相反。

**超级面板的交互（官方说明）**：

- 默认**长按鼠标右键**弹出，可改为其他方式（用户实际可设为中键）。
- 开启"英文快速翻译"后：选中文字 → 按弹出键 → 译文直接显示在面板顶部 → 双击文字区域复制（[官方专题页](https://www.u-tools.cn/plugins/topic/44/)）。
- 面板同时承载"对选中数据的后续操作"（搜索、复制、AI、OCR 等）。

**可借鉴**：

- "选中 → 按键 → 结果就在手边"的路径，不打开独立窗口。
- 结果置顶显示、双击复制，减少鼠标移动。
- 面板内容按上下文变化（有选中文本时优先给翻译）。

**不照搬**：

- 插件平台与工具集合（v1.0 只做翻译）。
- Electron 的体量与内存开销。
- 长按手势（本项目用"按下即触发"，更干脆）。

## 3. 对我们的启示

| 结论 | 落到产品上 |
|---|---|
| 用户对这类工具的期待是"按一下出现、按一下消失" | 卡片非激活、Esc/点外部即关、无安装负担 |
| 面板式交互比独立窗口更顺手 | 结果卡片贴着光标出现，而不是居中大窗口 |
| 体量是体验的一部分 | 单文件 60–90MB、常驻 ≤100MB、启动 ≤2s |
| 中键是"顺手但冲突"的键 | 默认中键 + Ctrl 旁路 + 可改键 |
| uTools 的翻译结果要求"在面板里就能读完" | 卡片宽度 420、最多 3 行原文折叠、译文流式 |

## 4. 未采用的方向及原因

| 方向 | 原因 |
|---|---|
| 做插件平台 | 与"单一功能、轻量"冲突，v1.0 明确不做 |
| Electron / Web 技术 | 体量与内存不符合目标；本机也没有 Node 环境 |
| 长按手势触发 | 学习成本高、与"按下即触发"相比更慢 |
| 自动划词翻译（不按键） | 误触发风险高，且用户对后台采集敏感 |
